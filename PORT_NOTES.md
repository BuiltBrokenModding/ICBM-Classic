# Port notes

Running log for the 1.12.2 → 1.21.1 port. See `PORTING.md` for conventions.

## Signature changes

- `CommonProxy#preInit()` → `preInit(IEventBus)`; `postInit`/`loadComplete`/`doLoadModels` and the GUI handler methods removed.
- `ICBMCreativeTab` is no longer a `CreativeModeTab` subclass; it owns the `DeferredRegister` and `TAB` holder.
- `ICBMClassic.chemicalPotion`/`contagiousPotion` are `DeferredHolder<MobEffect, ContagiousPoison>`.
- `ICBMSounds#getSound()` resolves a `DeferredHolder`; `ICBMSounds.register(IEventBus)` replaces the registry event.
- Tile `register()` methods only register packet codexes.
- `RadarMap`/`RadioMap.dimID` and `RadarRegistry.getRadarMapForDim(...)` use `ResourceKey<Level>`; radar/radio registries ignore client levels.
- Commands run on Brigadier through `ICBMCommands.register(dispatcher)`; sub commands keep their 1.12 handlers via a greedy args argument.
- `INBTSerializable` uses NeoForge Provider signatures everywhere; `CapabilityPrefab` lost its 1.12 capability methods.
- `IGPSData#setWorld(ResourceKey<Level>)`, `getWorldId()` returns `ResourceKey<Level>`.
- ICBM `@Cancelable` events implement `ICancellableEvent`; `EVENT_BUS.post` returns the event (check `isCanceled()`).
- `MissileChunkEvent.ticket` is a NeoForge `TicketController`.
- `ForgeRegistryHelpers.contains` takes a vanilla `Registry<V>`; `EventTrackerHelpers.getWorldId` returns a String.
- `Location(ILocation)` constructor removed; dimension saved as string in NBT, resource key in buffers.
- `ProjectileBlockInteraction` material interactions keyed by `TagKey<Block>`.
- `Blast` no longer extends `Explosion`; adds `asVanillaExplosion()`, `getAffectedBlockPositions()`, `getBlockResistance(pos, state)`, `fireDetonateEvent(list)`.
- `IThreadCallBack.getResistance` takes a `BlockState`. `EnderBlastCustomization` stores `ResourceKey<Level>`.
- `Poison` extends `MobEffect` `(name, color)`; `CustomPotionEffect` takes `Holder<MobEffect>`.
- Damage sources are data-driven (`ICBMDamageTypes`); `DamageSourceRedmatter.create(Level, RedmatterLogic)` replaces the subclass.
- `EntityFlyingBlock#getBlockGravity()` (vanilla `getGravity()` is final). `CapabilityEMP.EMP` aliases `EMP_ENTITY_CAPABILITY`.
- GUI prefab: `GuiContainerBase<T>` generic; `ContainerBase(MenuType, int, Player, H)`; `IGuiComponent` takes `GuiGraphics`; `IToolTip.getToolTip()` (renamed to avoid vanilla clash).
- `TileMachine(BlockEntityType, BlockPos, BlockState)`. Explosive block `EX_PROP` removed: read `TileEntityExplosive.EXPLOSIVE_PROPERTY` / the EXPLOSIVE component.
- Cruise launcher packet codex id `cruiselauncher` (was `cruiseLauncher`).

## Behaviour differences

- Loot: 1.12 added ICBM entries into the vanilla `main` pool. 1.21 pools are immutable, so an extra pool is
  added. Dungeon/mineshaft chests get one extra roll (100-weight empty entry plus the original weights).
  Creepers and blazes drop 0-9 sulfur **in addition** to gunpowder instead of sometimes replacing it.
- Saved UUIDs use the 1.21 int-array format. Worlds from 1.12 are not migrated (datafixers removed).

- Commands: the dimension argument takes a name (`minecraft:the_nether`), but `0`, `-1` and `1` still work. Bad numbers show Brigadier's errors. Explosive ids and dimensions are tab-completed.
- Kept 1.12 quirks: `/icbm lag` reads its radius from the second argument; ActionSpawnEntity randomises yaw when pitch is missing.
- BlockEditHandler runs server side only, in both level tick Pre and Post (matches 1.12 START+END throughput).
- InventoryUtility compares stack component patches instead of NBT.
- Threaded blast code uses `ThreadLocalRandom` (the 1.21 level random rejects concurrent use).
- Explosive variant models use baked-model wrappers (`client/mapper`) instead of an item property.
- Bomb cart uses its own fuse (vanilla TNT minecart fuse is private). Radar gun hitX bug fixed.
- JEI dynamic recipes are display-only shapeless recipes with per-stack id suffixes.
- Launcher connector refreshes its side states on block/shape updates only.

## Assets/data (worker F)

- Textures moved to `textures/block` and `textures/item`. Lang is now `lang/<locale>.json`, generated by `scripts/lang_to_json.py`
  using `scripts/lang_extras.json` for the new keys: entity, effect and death `.player` messages. `%d`, `%f` and `%1%d` became `%s`/`%n$s`.
  The unused legacy `%x %y %z %p %j` placeholders were left as they are.
- Recipes are in `data/icbmclassic/recipe/` with the same ids as 1.12, lower cased (`explosives/condensed`, `tools/rpgballistic` ...). They were generated by
  `scripts/convert_recipes.py`. Gating by ConfigItems.ENABLE_* now uses `neoforge:item_exists` conditions, and ore checks use `neoforge:tag_empty`.
  `lib/recipe/*` (the 1.12 JSON factories) and `RecipeGeneration` (an unused dev-time generator) were deleted because
  the static JSON now does their work.
- `ResourceConfigList`: fuzzy `~` keys now really match the content path (in 1.12 they were dead code because of the key lookup and compared the wrong path).
  Block metadata entries (`mod:block@2`) are rejected with a logged error; use `mod:block[prop:value]`. Item metadata entries match the damage value.
- Damage types `data/icbmclassic/damage_type/*`. Redmatter is in bypasses_armor, bypasses_effects, bypasses_enchantments
  and bypasses_shield. Fragments and projectile are in is_projectile. Chemical, contagious, spikes, radioactive_block,
  projectile and bomblet are in no_knockback. Fragments are in always_kills_armor_stands.

## Runtime audit fixes (2026-10-16)

A static audit after the first in-game crash (particle atlas lookup) found and fixed about 140 runtime, multiplayer, persistence and asset problems. Notes the fixers left, by area:

### Core and registries

- Config reload: the ICBMClassic reload listener hands ConfigMain.onConfigReloaded to the server thread via ServerLifecycleHooks.getCurrentServer().execute(...) when it fires on another thread (the NeoForge file-watcher thread, or the client thread when saving from the config screen). On a client connected to a remote server there is no local server, so it still runs inline on the calling thread; the server-side lists are not used there.
- New client-only entry point icbm.classic.ICBMClassicClient, annotated @Mod(value = icbmclassic, dist = Dist.CLIENT). It registers IConfigScreenFactory -> ConfigurationScreen::new, so the Mods list has a Config button again, as in 1.12 Forge @Config. Entries without @Config.LangKey use NeoForge's default label key icbmclassic.configuration.<entry name>. The en_us keys for these were sent to the assets area.
- Mekanism: projectile teleport through the teleporter frame needs a public no-arg TileEntityTeleporter#teleport(), which Mekanism 10.x for 1.21 most likely lacks. MekProxy now detects this once in init(), logs a single warning and leaves the frame unhooked, so projectiles hit it like a normal block. A real 1.21 port of this compat would need the Mekanism 1.21 teleport API (PORT-TODO candidate for Open items).
- Space chicken: the icbmclassic:space_chicken attachment is now only created by setSpace, and only true is serialized. Chickens saved earlier with space_chicken:0b load as false and drop the entry on their next save.
- Mob effects icbmclassic:chemical and icbmclassic:contagious stay registered (PORTING.md contract). Their icons are new PNGs requested under textures/mob_effect/ in the assets area.
- NeoForge 21.1 ModConfigSpec validates restart types per config type: WORLD only on COMMON/SERVER, GAME only on CLIENT/COMMON. Any future @Config.RequiresMcRestart or RequiresWorldRestart mapping in ConfigLoader must respect this, or startup throws. No ICBM field uses these annotations today.
- ExplosiveInit.encodeEnderCoordSet now sends Component.translatable for chat.launcher.toolTargetSet and chat.launcher.noTargetInTool, so the text is resolved on each player's client, which fixes language on dedicated servers.
- CapabilityMissileStack.newMissile resets health after the explosive stack is set, so tier 2 to 4 explosive missiles start at full tier health. 1.12 had the same bug, so this is a deliberate change from 1.12 behaviour.

### Client rendering

- RenderFragments: the anvil branch now adds the +90 degree Y rotation that 1.12 renderBlockBrightness applied internally, the same pattern as vanilla 1.21 TntRenderer.
- RenderLightBeam: each beam wall is emitted twice, once per winding, because RenderType.beaconBeam culls back faces and 1.12 used disableCull. The vertex count per tube doubles from 16 to 32, which is negligible.
- GuiButtonBase: keyboard activation (Enter, Space, keypad Enter) is disabled for all ICBM buttons to match 1.12 GuiButton. Tab focus navigation still moves focus, but pressing Enter on a focused ICBM button does nothing.

### Launchers

- Launcher firing_package (TileLauncherBase and TileCruiseLauncher) is now restored on load, so a delayed or aiming launch survives save/quit and chunk unload. 1.12 silently dropped it. The package is not restored on the client (the client never ticks it). onTriggerCallback (the radio trigger feedback) is not saved, so a restored package fires without calling back the original sender.
- BlockLaunchConnector.isConnection treats any ILauncherComponent neighbour as connected without checking capabilities. This matches the 1.12 getActualState steady state and avoids a stored 'disconnected' face when the neighbour's network forms a tick later. Other mods' tiles that gain energy or item caps without a block update still do not refresh the connector state.
- BlockLaunchScreen no longer uses BlockICBM.dropInventory. It drops its own battery slot in onRemove. 1.12 deleted the battery, because the screen only exposes the network inventory.
- TileCruiseLauncher.PACKET_GUI is now fromServer(). It was fromClient() in 1.12, where direction was never checked, so with the port's server-side direction check it was a client-to-server exploit.
- TileLauncherBase.PACKET_GUI and TileLauncherScreen.PACKET_GUI now include energy, so the GUI energy bars update. In 1.12 they showed only the value from chunk load.
- ContainerLaunchBase shift-click now uses firstPlayerSlotCheck 2. In 1.12 it was effectively 1, so the battery could not be shift-clicked out.
- LauncherLangs.ERROR_NO_LAUNCHER is fixed to info.icbmclassic:launcher.error.network.launchers. In 1.12 a missing dot meant the key was never translated.
- Cruise launcher: currentAim is only stepped on the server. It now reaches clients because setChanged() runs on every tick the turret is not aimed, which sends the description packet through TickDoOnce. Before, it rode on the per-tick inventory setChanged.
- Launcher base: updateSeat now drops a reference to a seat that was removed (discarded, or unloaded with its chunk) so a fresh seat can be spawned. EntityPlayerSeat#tick makes a saved seat that loads later yield to the new one.

### Machines (EMP tower, radar, explosive blocks, energy)

- The EnergyBuffer extraction fix changes machine behaviour on purpose: consumePower(cost, simulate=true) now needs the full cost stored. Before (1.12 included) any non-zero energy passed, so EMP tower, launcher and cruise checks were effectively free. The per-tick upkeep (radar, EMP) still drains down to 0 through partial extraction, as before.
- The radar station now consumes ConfigRadar.POWER_COST once per tick, as the config comment says. 1.12 consumed it twice per tick (once in update and again inside getRadarState).
- Battery discharge into the EMP tower is now limited to ConfigEmpTower.ENERGY_INPUT per tick without destroying the excess. 1.12 drained the battery by the free buffer space and lost everything above the limit.
- The InventoryWithSlots change removes the per-tick description packet spam for the launcher base, cruise launcher, launcher screen, EMP tower and radar. Any launcher-area sync that relied on it must now call setChanged itself: the cruise launcher aim (external request above) and the launcher base GUI codexes (the related finding that the launcher area owns).
- EMP tower PACKET_DESCRIPTION layout changed (two leading ints: range, energy). Client and server share the codex, so no protocol id change.
- Explosive blocks placed without an item (/setblock, /fill, structures) now trigger as explosive id 0 (condensed), as 1.12 meta 0 did. Their client model still gets ModelData.EMPTY until triggered; the client-area explosive block model should handle a missing EXPLOSIVE_PROPERTY with the id 0 texture if that is not already done.
- zh_cn.json and ru_ru.json still store the red matter taunt lines under the old icbm.explosive.redMatter.info.* keys, so they fall back to en_us. The assets area could rename them to explosive.icbmclassic:redMatter.info.* if it wants those translations used. Low priority: as the requester noted, the red matter branch in getDetailedInfo cannot be reached, the same as in 1.12.

### Missiles

- Missiles (Arc and old Ballistic flight logic) now go into the missile tracker when their next 2-tick path enters any chunk where entities do not tick: outside simulation distance, a border chunk, or an unloaded chunk. In 1.12 the check was only 'chunk unloaded'. 1.21 freezes entities in loaded chunks outside simulation distance, and ChunkEvent.Unload fires after the entities are already removed, so the 1.12 chunkUnload rescue cannot fire.
- MissileTrackerHandler.canEntitiesTick and canEntitiesTickBetween rely on ServerLevel.isNaturalSpawningAllowed(ChunkPos) (entityManager.canPositionTick) and isNaturalSpawningAllowed(BlockPos) (DistanceManager.inEntityTickingRange), plus ChunkPos.getWorldPosition(), all in 1.21.1 Mojmap. EntityMissile overrides NeoForge's Entity#onAddedToLevel() and calls super.
- On world load the missile tracker sends missiles that were waiting to spawn back through the arrival step (force chunks, then wait 5 s), because the ticket controller releases all forced chunks on load. A spawn now waits for the target chunk to tick entities, up to 6 extra preload cycles.
- The missile engine sound is now played only on the client. Every client that tracks the missile ticks it, so the server no longer sends a per-tick ClientboundSoundPacket. MISSILE_LAUNCH is still played by the server in CapabilityMissile.launch.
- WarmupFlightLogic now saves and syncs 'timer'. Older saves without it load as 0, which means the warm-up is already done, the same as before.
- EntityMissile.PACKET_DESC is now marked fromServer(). Clients can no longer push missile save data (target, flight logic) to the server through this codex.

### Blasts

- Threaded blasts (BlastThreaded subclasses, BlastBeam, ThreadExplosion subclasses) no longer read the Level from worker threads. They read content/blast/thread/ChunkSnapshot, which references the loaded LevelChunks around the blast, captured on the server thread via ChunkSource#getChunkNow. Use Blast#getBlockStateThreaded / #isLoadedThreaded (or ThreadExplosion#snapshot) in any worker code. Chunks not loaded at capture time are treated as not loaded and are never loaded by a blast. Modded Block#getExplosionResistance overrides that read the level still go through the slow cross-thread path.
- Worker threads hand results back with Blast#scheduleOnServerThread (MinecraftServer#tell(new TickTask(...))), never MinecraftServer#execute. execute runs the task inline on the worker once the server is stopping. Tasks are dropped if the server stopped or the level was replaced.
- Blast#destroyBlockByBlast passes the real radius as LootContextParams.EXPLOSION_RADIUS, so loot tables apply the 1/radius drop chance that 1.12 used.
- Blast#markVelocityChanged(entity) sets hurtMarked on ServerPlayer after a server-side velocity change, so attract/repel, sonic, anti-gravity and ender pull now move players (1.12 never did).
- Behaviour changes from 1.12 (all bug fixes): anti-gravity entity AABB uses x + radius (1.12 typo used y); the ender blast random target is on the surface (gap search in ceiling dimensions) and GPS targets in another dimension use Entity#changeDimension; the nuclear/thermobaric smoke cloud and the ender explosion particle are now sent to clients (in 1.12 they were server-side no-ops), the cloud to players within 256 blocks.
- BlastShrapnel and BlastMutation (one-shot, non-tickable blasts) now return true from doExplode, so they finish at once and leave WorkTickingActionHandler.activeBlasts. In 1.12 they returned false and stayed in that list until world unload.

### Gas, redmatter, radiation

- Redmatter: the 1.12 bug that loaded blast_size_max into the current size on NBT read is fixed. A redmatter reloads at the size it was saved with and keeps its max size. A size-70 redmatter saved by the earlier buggy port loads at 70, as it was saved.
- Redmatter: block raytraces use ClipContext.Fluid.SOURCE_ONLY to match 1.12 rayTraceBlocks(stopOnLiquid=true), which collided with liquid source blocks only.
- Radiation default replacement list: leaves are matched with `instanceof LeavesBlock` because block tags are not bound during FMLCommonSetupEvent, when the list is first built. BlastBlockHelpers.isPlantMaterial (blastsCore) still uses BlockTags.LEAVES, which is fine for runtime callers. Any other caller that runs before tags bind would have the same problem.
- BlastColor: particle colors are normalized from the signed ColorB bytes to 0-1 floats. 1.12 passed the raw byte values, so the colors came out wrong there too; this is a fixed copied bug.
- BlockRadioactive: the wither duration now comes from the decayWitherDuration config instead of a hard-coded 20 ticks. The default (20) gives the same result.

### Entities

- EntityPlayerSeat: a seat saved to disk that loads after the launcher has already spawned a seat now removes itself. The exception is a seat that returns carrying a rider (a player's RootVehicle on rejoin); it takes over and the launcher's empty seat is discarded. On the server, a seat whose launcher no longer points to it (host.seat != this) is discarded, so duplicate seats already saved in existing worlds clean themselves up the first time they tick.
- EntityFlyingBlock spawn data no longer includes the block_entity and source_stack tags. On the client, getBlockData().getSourceStack() falls back to stone and getTileEntityData() is null. Client code should only use getBlockState().
- EntityICBM.hurt now always returns false on the client, like vanilla LivingEntity. Health and destruction are decided only on the server.
- EntityICBM loads 'health' raw, without clamping to getMaxHealth(). Missiles and bomblets whose max health depends on data loaded later (explosive tier) keep their saved health after a reload.
- Possible follow-up for the missiles area, same behaviour as 1.12 and not changed here: EntityExplosiveMissile's constructor calls setHealth(getMaxHealth()) before the explosive is set. Newly created tier 2-4 explosive missiles therefore start with tier-1 health while their max health shows the higher tier.
- Cargo parachute and balloon: the 'expire when empty' check is now server-only. In ITEM mode the cargo item is mounted before it is added to the world, so the item's spawn bundle carries the passenger link. PROJECTILE and ENTITY modes still mount after adding; the server-only check stops the client from discarding the holder, and the passenger link arrives in the next tracker tick.
- EntitySmoke: worlds saved before this fix have no green or blue keys, so smoke reloaded from them stays red (defaults 0/0). Newly saved smoke keeps its colour.
- EntityExplosive: worlds saved before this fix keep their already-wrapped byte fuse values; only new saves store the full int.
- EntityExplosion#onRemovedFromLevel now untracks its Blast from WorkTickingActionHandler.activeBlasts (server side only, and only when the blast's controller is this entity). The orphaned Blast from an unloaded chunk is no longer ticked, but a BlastThreaded worker thread that was already running is not killed here and simply finishes unused. This is the same as 1.12, which had no unload hook at all.

### Items and actions

- Behaviour difference (rocket launchers): the reload delay is now the vanilla item cooldown (20 ticks = 1000 ms), set on the server after a missile spawns. The hotbar shows the cooldown sweep, and it applies to every player, including creative and dedicated-server players. In 1.12 it was a client-only HashMap of click times keyed by player name, which a dedicated server never checked.
- Parity restored: the rocket launcher and ballistic launcher stack to 64 again (the port had stacksTo(1); 1.12 never set a max stack size). If the maintainer prefers 1 for a handheld weapon, change it back to new Item.Properties().stacksTo(1) in ItemRocketLauncher and add a Behaviour differences entry.
- Behaviour difference (grenade): holding a grenade for the full 3 s (60 ticks) now throws it automatically at full power through finishUsingItem. In 1.12 the use finished without a release and the throw was lost.
- Behaviour difference (radar gun, laser designator): both work from the off hand (the packet carries the off-hand slot 40). The server drops targets that are non-finite or more than range + 8 blocks from the player's eyes (range 200).
- Behaviour difference (world unload): WorkTickingActionHandler no longer discards a blast's live controller entity (EntityExplosion) on LevelEvent.Unload. It only drops the blast from the tracker and kills an old-style ThreadExplosion if one exists. In 1.21, ServerLevel#close saves entities after the Unload event, so the discard would have deleted running gas, sonic, beam, ender and antigravity blasts from the save. In 1.12 the Unload event ran after saving, so the entity survived and resumed through IBlastRestore, and that still happens now. Blasts without a controller (threaded, one-shot) are still cleared. activeBlasts is also cleared on ServerStoppedEvent.
- Persistence fix: a PotentialActionImp pre_check loaded from NBT is init'd lazily on the server only (first update() or checkAction() with a server level). Saved or reloaded cluster missiles (ConditionAnd of ConditionalImpact and ConditionTargetDistance) now deploy, where 1.12 and the earlier port left them stuck on MissingFieldStatus. The client copy built from spawn data stays uninitialised on purpose, as before.
- Not changed (outside the findings): ItemLaserDetonator.use and ItemRadarGun.use still return success for their instant use, so the arm swings. Their finishUsingItem cooldown reset in ItemLaserDetonator is dead code because use() never calls startUsingItem.

### Networking and saving

- Networking: in 1.21 memory connections (singleplayer, LAN host) hand the sender's CustomPacketPayload object to the receiver without running the StreamCodec. ICBMPayload now carries a `decoded` flag, and PacketManager.handle round-trips undecoded payloads through ICBMPayload.STREAM_CODEC, encoding with the sender's RegistryAccess and decoding with the receiver's. Handlers can always assume decodeInto ran. New packet types need nothing extra.
- Packet security (new compared with 1.12): PacketLambdaTile only accepts client-sent codexes flagged fromClient(), and only when the sender has that tile's ContainerBase menu open (host == tile && stillValid). Any new client-to-server tile codex must be sent from the tile's own GUI or it will be rejected. PacketLambdaEntity accepts only codexes explicitly marked fromClient()/asServerOnly() from clients; bidirectional (default) entity codexes are rejected server side.
- PacketCodex direction flags are still not checked client side (no security value; avoids depending on the TileCruiseLauncher.PACKET_GUI flag fix).
- InventoryUtility.dropInventory resolves the IItemHandler from the block entity (ICapabilityHolderTile) because Block#onRemove runs after the chunk already holds the new state. A 3-arg overload dropInventory(level, pos, oldState) exists for non-ICBM tiles.
- WorkerThread: a failing threaded-blast task is logged and its onCompleted still runs, so the blast applies partial edits and ends instead of killing the only worker.
- RegistryHelper.access() returns the client's registries when called on the client thread, even in singleplayer. Elsewhere it returns the server's.
- NbtSaveRoot skips empty StringTags on save, as 1.12 did (NBTTagString#hasNoTags).
- nodeItemStack now sends a copy of the stack taken when the packet is built, because 1.21 encodes on the netty thread and the server thread may change the live stack in the meantime.
- WorkerThread drops tasks that finish after stopTasks() (ServerStoppingEvent) and does not call onCompleted for them. This also applies to tasks that fail with an exception during shutdown.

### Projectiles and radar

- RadarRegistry#chunkUnload now listens at EventPriority.LOWEST so MissileEventHandler#chunkUnload (NORMAL) always sees the chunk's radar contacts first. This restores the 1.12 handler order. In 1.12 it came from registration order (RadarRegistry was registered in preInit); in the port RadarRegistry is registered in the mod constructor, before FML injects @EventBusSubscriber classes.
- Radar contacts are now bucketed by floor-based chunk coordinates (1.12 used (int) truncation, which misfiled entities near negative chunk borders). RadarMap.update compares ChunkPos with equals (1.12 compared by reference, so it re-filed every contact every second). RadarEntity.equals has an identity check so dead or unloaded contacts are actually removed from chunk lists.
- EntityProjectile skips the block ray trace when motion is effectively zero (velocity <= 1e-7). In 1.12 this returned null on a NaN ray; in 1.21 it would synchronously look up or load block (0,0,0) every tick, for example for every missile during warmup.
- EntityProjectile.changingDimensions is cleared when changeDimension returns the same instance (same-level teleport such as End gateways) or fails without removing the entity. Otherwise block impacts stayed disabled forever.
- Intentional behaviour fixes over 1.12: CachedProjectileData now actually caches (snowballs and eggs in cluster missiles, parachutes or balloons spawn as thrown snowball and egg entities, not item drops). Spectral arrows spawn a real SpectralArrow. Any SpawnEggItem, including NeoForge DeferredSpawnEggItem from other mods, converts to an entity-spawn projectile through a generic check in ProjectileDataRegistry.find (after registered conversions, so API conversions still take precedence).

### Config and commands

- Config lists (EMP replacements, radioactive replacements, cluster item sizes and ban/allow lists, protective armor): the KEY_VALUE, META_KEY and BLOCK_PROP namespace groups no longer accept ':', '=' or '['. User entries like `minecraft:stone=icbmclassic:radioactive_stone` and `minecraft:dirt=minecraft:oak_log[axis:y]` now work; in 1.12 they were always rejected as 'Invalid resource location'.
- A parser exception inside a config list (ResourceConfigList.load) is now logged as an error and recorded as a parse issue for that entry. It no longer escapes FMLCommonSetupEvent and fails mod loading.
- BlockChanceOut: an entry whose output block fails to parse is now rejected with an error. In 1.12 it silently became 'keep the existing block', which also overrode the default replacement. `~` still means keep. `@chance(1)` (no decimal point) is now accepted. The legacy `block,chance` form splits on the last ',' and is skipped when the value ends in ']', so property outputs with several properties are not split.
- @domain:<mod>=<value> now accepts multi-character values (for example 0.5 or true). 1.12 only accepted a single character.
- /icbm lag [radius] now uses the first argument; 1.12 read args[1], so the radius was ignored.
- Not fixed, pre-existing from 1.12 and out of scope: BLOCK_PROP_REGEX property values are `[\w.]+`, so the fuzzy property values (`prop:~`, `prop:~x`, `prop:x~`) that collectBlockProps handles can never be reached from an entry. collectBlockProps' fuzzy branch also uses substring(1) for a trailing '~' and inverts starts/ends compared with getFuzzyValue. A separate fix should allow '~' in the regex and correct that branch.
- Not fixed, pre-existing: BlockChanceOut splits the value on ';' before matching @nbt(...), so NBT strings containing ';' break the entry. An error is logged; it no longer crashes.
- The user's crash report (NeoForge 21.1.257) shows the game got through config registration even though the committed ConfigLoader gave worldRestart() to the 8 fields of ConfigItems, a STARTUP config. So 21.1.257 either does not check restart type against config type at registration, or it allows WORLD on STARTUP. The new mapping only uses combinations that work either way (no marker on STARTUP, GAME only on CLIENT or COMMON, WORLD only on COMMON or SERVER). It does depend on ModConfigSpec.Builder#gameRestart() existing, which I believe is in NeoForge 21.1 along with the ConfigurationScreen and RestartType API.
- The same crash report lists the data pack 'mod/icbmclassic (incompatible)'. Commit 0dbc21d already changed pack.mcmeta to supported_formats 34..48, so this should be gone in the next build. Core should confirm it.

### API

- MetaTag no longer uses Lombok @Data. equals and hashCode are based on the key, and the tags are deduplicated by key in TAG_MAP (the 1.12 code stored them by path, so find() never matched). The 1.12 bugs this fixes (StackOverflowError when hashing or printing any tag that has a parent or children, and MetaTag.find always returning null) could only be reached through the addon action-listener and ActionProvider API.
- AbstractPos#rayTraceBlocks stop-on-liquid (b1) now maps to ClipContext.Fluid.SOURCE_ONLY, matching 1.12, where rays stopped only on source blocks.

### Assets and lang

- Assets: bomb cart item models now use minecraft:item/tnt_minecart and the anvil missile uses minecraft:block/anvil; both were 1.12 texture names that the 1.13 flattening renamed. ### Data (recipes, tags, damage types)

- Damage types `data/icbmclassic/damage_type/*`. Redmatter is in bypasses_armor, bypasses_effects, bypasses_enchantments and bypasses_shield. Chemical, contagious, spikes, radioactive_block, projectile and bomblet are in minecraft:no_knockback (1.12 sources with no true source gave no vanilla knockback; 1.21 would otherwise push in a random direction). Fragments (msgId arrow) are in minecraft:always_kills_armor_stands, so they break armor stands like 1.12 'arrow' damage.
- Recipes: the Mekanism atomic alloy is mekanism:alloy_atomic in Mekanism for 1.16+ (the 1.12 id was mekanism:atomicalloy). explosives/mekanism/* and the not-item_exists conditions in explosives/vanilla/* use the new id.
- Recipes: 1.12 ExRecipeFactory read the result count from the top-level recipe object instead of result, so in 1.12 every icbmclassic:explosive recipe gave 1 item. This port honours the counts the JSON authors wrote (condensed 3, anvil 10, smoke 16, breaching 2, contagious 2, debilitation 3), treating the 1.12 behaviour as a bug.
- Remaining minor difference, not changed: 1.12 'arrow' fragments only knocked back when shootingEntity was non-null (knockback needed getTrueSource()). In 1.21 they always knock back 0.4 away from the fragment, same as vanilla arrows without an owner.
